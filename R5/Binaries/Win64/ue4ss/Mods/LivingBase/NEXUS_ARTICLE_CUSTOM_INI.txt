[size=5][b]Living Base Enhanced — Custom-*.ini Drop-In Content[/b][/size]
[color=#D4D4D8]Living Base Enhanced lets you add your own spawn-menu content — decor, signs, people, monsters, animals, poses, and hand items — without editing any mod files or waiting on an update. Drop in a text file, point it at real game assets, and it shows up in the spawn menu alongside everything built in. This article covers how to set it up and every option available for each content type.[/color]


[size=4][b][u]Getting Started[/u][/b][/size]
[list=1]
[*][color=#D4D4D8]Go to [b]..\Windrose\R5\Binaries\Win64\ue4ss\Mods\LivingBase[/b].[/color][/*]
[*][color=#D4D4D8]Copy [b]Custom-Template.ini[/b] (included with the mod — if you don't have it, it's also attached to this article) and rename the copy, keeping the [b]Custom-[/b] prefix and [b].ini[/b] extension — for example [b]Custom-MyStuff.ini[/b]. Whatever comes after [b]Custom-[/b] becomes that file's own name in the spawn menu, so pick something recognizable.[/color][/*]
[*][color=#D4D4D8]Open (or create) [b]CustomFilesIndex.txt[/b] in that same folder and add your new filename as its own line — this is what tells the mod to actually load it. A line starting with [b];[/b] is a comment.[/color][/*]
[*][color=#D4D4D8]Edit your Custom-*.ini file and fill in real asset paths (see the breakdown below for what each content type needs).[/color][/*]
[*][color=#D4D4D8]Either restart the game, or in-game open the Spawn Tree and click the [b]Update[/b] button next to the filter box — it re-scans your files and refreshes the menu on the spot, no restart needed.[/color][/*]
[/list]
[color=#D4D4D8][i]Don't know an asset's path? Target-lock something similar already in the world and read its class off the Target List tab, or check the pakcontents.xlsx reference spreadsheet (from the Windrose UE4SS Modding Notes resource) for a searchable list of every asset in the game.[/i][/color]


[size=4][b][u]Where Your Content Shows Up[/u][/b][/size]
[color=#D4D4D8]Everything from one Custom-*.ini file is grouped together under its own named branch, so your content stays clearly separate from any other pack you or someone else installs — nothing gets mixed together just because two files both add decor.[/color]
[list]
[*][color=#D4D4D8]Decor / Signs / People / Monstrous / Animals: main Spawn Tree, under [b]Custom Content > (your file's name) > (type) > (category) > (name)[/b][/color][/*]
[*][color=#D4D4D8]Poses: Custom tab > Poses and Actions, under [b]Custom > Poses > (your file's name) > (category) > (name)[/b][/color][/*]
[*][color=#D4D4D8]Hand Items: Custom tab > Poses and Actions > Hand Item Transform's tree, under [b]Custom > Hand > (your file's name) > (category) > (name)[/b][/color][/*]
[/list]


[size=4][b][u]Type-by-Type Breakdown[/u][/b][/size]
[color=#D4D4D8]Each [b][Section Name][/b] in your ini file is one entry. [b]type[/b] is always required; everything else below is optional unless marked [b](required)[/b].[/color]

[color=#D4D4D8][b]type = decor[/b] — a static or Blueprint prop placed in the world.[/color]
[list]
[*][color=#D4D4D8][b]path[/b] (required unless kind = effect): the asset path — a Blueprint class ending in [b]_C[/b] for kind = actor, or a bare static mesh (no [b]_C[/b]) for kind = mesh.[/color][/*]
[*][color=#D4D4D8][b]kind[/b]: [b]actor[/b] (default, path is a real Blueprint class spawned directly) | [b]mesh[/b] (path is a bare static mesh, wrapped so it can still collide/be solid) | [b]effect[/b] (a pure visual effect with no mesh at all — see fx below; path can be left out entirely).[/color][/*]
[*][color=#D4D4D8][b]fx[/b] (kind = effect only): the Niagara System asset path to attach.[/color][/*]
[*][color=#D4D4D8][b]category[/b]: where it nests under your file's Decor branch — use " > " to nest deeper, e.g. "Lights > Torches".[/color][/*]
[*][color=#D4D4D8][b]label[/b]: display name override (defaults to the entry's [Section Name]).[/color][/*]
[*][color=#D4D4D8][b]solid[/b]: true | false — whether the prop blocks movement. Left out, it follows the mod's global decor-collision setting.[/color][/*]
[/list]

[color=#D4D4D8][b]type = sign[/b] — same actor/mesh placement as decor, but can also carry text via the Signs tab.[/color]
[list]
[*][color=#D4D4D8][b]path[/b] (required), [b]kind[/b] (actor or mesh — no "effect" option for signs), [b]category[/b], [b]label[/b], [b]solid[/b] — all the same as decor, above.[/color][/*]
[*][color=#D4D4D8]Text-layout fields (all optional — an untuned sign still accepts text, just maybe not perfectly placed on the mesh): [b]x, y, z[/b] (the text's anchor point on the sign), [b]depth[/b] (how far in front of that anchor the text floats), [b]yaw, pitch, roll[/b] (facing/tilt), [b]bw, bh[/b] (board width/height the text must fit inside), [b]size[/b] (largest text size allowed), [b]rows[/b] (max text lines).[/color][/*]
[*][color=#D4D4D8]To tune these: spawn the item, then run [b]lbtestsigntext <text> x= y= z= yaw= pitch= roll= bw= bh= size=[/b] on it in-game, and copy the final numbers back into your ini file.[/color][/*]
[/list]

[color=#D4D4D8][b]type = people[/b] / [b]monstrous[/b] / [b]animals[/b] — a Blueprint character, monster, or animal class.[/color]
[list]
[*][color=#D4D4D8][b]path[/b] (required), [b]category[/b], [b]label[/b] — same as decor, above.[/color][/*]
[*][color=#D4D4D8][b]idle[/b]: true — spawn frozen in place instead of walking.[/color][/*]
[/list]

[color=#D4D4D8][b]type = pose[/b] — an animation applied to whatever's currently target-locked.[/color]
[list]
[*][color=#D4D4D8][b]path[/b] (required): an animation asset (no class, no _C).[/color][/*]
[*][color=#D4D4D8][b]category[/b], [b]label[/b] — same as decor, above. (kind/solid/idle don't apply to poses.)[/color][/*]
[/list]

[color=#D4D4D8][b]type = handitem[/b] — an item equippable into a hand socket.[/color]
[list]
[*][color=#D4D4D8][b]path[/b] (required): a mesh or weapon asset (static or skeletal — auto-detected).[/color][/*]
[*][color=#D4D4D8][b]category[/b]: the item's grouping heading (Weapons/Tools/Bottles/Other, or your own) — one segment only, not nested.[/color][/*]
[*][color=#D4D4D8][b]label[/b]: the display name this item is applied/looked-up by. Defaults to the [Section Name].[/color][/*]
[*][color=#D4D4D8]Click its "+" in the Hand Item Transform tree to equip it on whichever hand (Left/Right) is currently selected there — the same panel's Move/Rotate/Scale controls then apply to it.[/color][/*]
[/list]


[size=4][b][u]Example File[/u][/b][/size]
[color=#D4D4D8]This is a trimmed example — a full template with every field documented is included with the mod ([b]Custom-Template.ini[/b]).[/color]
[code]
[My Decor Item]
type = decor
kind = actor
path = /Game/REPLACE/WITH/REAL/BP_SomeDecorItem.BP_SomeDecorItem_C
category = My Decor

[My Mesh-Only Decor Item]
type = decor
kind = mesh
path = /Game/REPLACE/WITH/REAL/SM_SomeStaticMesh.SM_SomeStaticMesh
category = My Decor
solid = true

[My Effect Item]
type = decor
kind = effect
fx = /Game/REPLACE/WITH/REAL/FX_SomeNiagaraSystem.FX_SomeNiagaraSystem
category = My Decor

[My Sign Item]
type = sign
path = /Game/REPLACE/WITH/REAL/BP_SomeSignOrFlag.BP_SomeSignOrFlag_C
x = 0.0
y = 0.0
z = 0.0
depth = -2.0
yaw = 0.0
bw = 100.0
bh = 50.0
size = 30.0

[My Person]
type = people
path = /Game/REPLACE/WITH/REAL/BP_SomeCharacter.BP_SomeCharacter_C
category = My Crew

[My Pose]
type = pose
path = /Game/REPLACE/WITH/REAL/AM_SomeAnimation
category = My Poses

[My Hand Item]
type = handitem
path = /Game/REPLACE/WITH/REAL/SM_SomeWeaponOrTool
category = My Items
label = My Cool Sword
[/code]


[size=4][b][u]Tips[/u][/b][/size]
[list]
[*][color=#D4D4D8]You can mix every type freely in one file — a single Custom-*.ini can add decor, a sign, a pose, and a hand item all at once.[/color][/*]
[*][color=#D4D4D8]Already-placed items are tracked by their resolved asset path, not by position in the file, so freely reordering or renaming entries in your ini later never corrupts anything you've already placed in the world.[/color][/*]
[*][color=#D4D4D8]If an entry doesn't show up after clicking Update (or restarting), double-check [b]type[/b] and [b]path[/b] are both set — those two fields are required for every entry — and that the filename is listed correctly in [b]CustomFilesIndex.txt[/b].[/color][/*]
[/list]
